# 病害小结接口

`POST /api-ai/diseaseSummary`，请求为 `application/json`，成功响应为 UTF-8 纯文本。

报告端按一个部位发送病害，并明确提供对象树中的部位名称：

```json
{
  "sectionName": "上部一般构件",
  "diseases": [
    {"biObjectName": "横隔板", "position": "底面", "type": "竖向裂缝", "crackType": "竖向", "quantity": 2, "description": "竖向裂缝2条，总长度2m"},
    {"biObjectName": "横隔板", "position": "侧面", "type": "竖向裂缝", "crackType": "竖向", "quantity": 3, "description": "竖向裂缝3条，总长度3m"}
  ]
}
```

## 分组规则

| sectionName | 模型请求分组 | 组内统计 |
| --- | --- | --- |
| 上部承重构件、上部承重结构 | biObjectName + position | 按 type、裂缝方向统计 |
| 其他部位，包括上部一般构件、支座、桥墩、桥台、墩台基础、桥面系各部位 | biObjectName | 按 type、裂缝方向跨位置统计 |

上述示例只产生一个横隔板请求，竖向裂缝的程序数量合计为 5。若将 sectionName 改为“上部承重构件”，则底面、侧面分别请求，数量分别为 2 和 3。

仅构件模式下，模型输入副本移除 position，提示词要求不根据 description 中的位置再次拆分。原始记录保持完整。位置名称不做同义词归并。模型选择阈值以完成分组后的记录条数判断，quantity 不参与阈值判断。

## 兼容与上线

- 旧 JSON 数组请求继续按 biObjectName + position 分组，因其未提供部位，服务不会猜测归属。实际报告调用已补传 sectionName。
- 对象请求必须包含非空字符串 sectionName 和非空 diseases 数组；不完整请求返回 400。
- 先更新 SpringAI，再更新报告服务。旧 SpringAI 不支持新的对象请求。
- 其他部位和旧数组请求沿用现有提示词及文本合并，报告排版逻辑保持不变。

## 上部承重构件正文

明确传入上部承重构件/上部承重结构时，每个构件和位置使用独立的承重提示词。AI 仍输出报告正文，负责描述中的尺寸提取与计算；程序按 type、裂缝方向累计 quantity，提供逐类别输出清单，并要求逐类输出数量、单位及原文明确标注的长度、面积、宽度。程序不将 AI 输出改为结构化尺寸 JSON。

模型只写正文，例如 `纵向裂缝2条，总长度3m，宽度为0.14mm；剥落18处，总面积0.8547m²`。构件名称、位置名称和序号由程序根据请求分组生成，避免模型漏标题或标题变化造成合并丢失。位置名称按输入保留，不合并内外、左右等不同位置。

程序逐类别校验名称、数量单位、类别覆盖及必需尺寸表达。缺失、重复、未知类别或不规范正文只重试该分组一次，并附具体错误；仍不合格时接口返回 502，拒绝将不完整正文作为成功结果返回。尺寸校验检查表达是否齐全，不保证 AI 算术结果正确；真实测试需另外核对原始记录。父响应按模型与提示词指纹隔离，承重和其他部位不会共用不同提示词的父响应。

父响应不发送空闲预热请求。Prompt Cache key 由配置前缀、system prompt 指纹和模型组成；同一父响应及其所有分组分支使用相同 key。两套提示词与两种模型最多形成四个稳定的缓存路由组，提示词内容变化时自动切换到新的 key。

## 实测请求记录

默认关闭。启动时设置 `--disease-summary.trace-directory=/absolute/test-directory`，每一次真正发送到 Responses API 的请求都保存为独立的 `*-request.json`，内容与 HTTP JSON 请求体一致，包含父响应初始化、分组正文、内容纠正、网络重试和缓存参数兼容重试。对应 `*-result.json` 记录 HTTP 状态、模型正文及 token 信息，失败则记录错误。不记录 HTTP 头或 API Key。

需要记录时目录必须可写；写入失败会使测试请求失败，避免出现未留存输入的模型调用。请求 JSON 含原始病害描述，应放在测试产物目录中保管，不默认启用到线上日志。
